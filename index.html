HANDS ON / STANDARD LIBRARY ONLY

Small repositories. Consequential bugs.

Download, unzip and run python3 -m unittest -v inside each folder. Python 3.11+. The initial tests intentionally fail. Solutions are separate, spoiler-marked downloads; they are not access-controlled.

THE 60-MINUTE SIMULATION

Deliver a patch you can defend.

Choose ledger or outbox. Spend 10 minutes mapping, 10 reproducing, 20 patching, 10 testing and 10 reviewing. Stop editing when the timer ends and record what remains.

60:00

Score the evidence, not confidence

Score each dimension 0–4. 0 = absent; 1 = assertion only; 2 = partially demonstrated; 3 = demonstrated against acceptance criteria; 4 = demonstrated plus a relevant failure or tradeoff analysis.

0 / 20

Suggested self-review: 16+ with no dimension below 2 → attempt a harder variant. Otherwise repeat the weakest dimension. These are practice thresholds, not a hiring prediction.

PRECISE LANGUAGE

Concepts you can explain plainly

Desk-side checklist

REPRODUCE → HYPOTHESIZE → FALSIFY
Contract: inputs, effects, errors, identity
Concurrency: owner, bound, cancellation
Retry: classification, deadline, stable key
Worker: delivery, acknowledgment, crash window
Performance: baseline, plan, query count
Review: regression, risk, rollback, next signal

Before a handoff, include the failing command, the invariant restored, tests run, remaining limits and the next measurement.
